## Approved matching layers and amount checks, 7 November 2026

Nurwan requested this change after the audit above. Rules still run in saved order, with each source row used once per stage. Composite rules now combine optional references, exact or bounded amounts, and a calendar date or time interval. The editor can select actual reference, amount and date columns. Bank rules support minimum and maximum arrival days. Missing references can be allowed; conflicting known payment references or store IDs cannot be ignored. Duplicate candidates stay open for review. A full withdrawal cannot be assigned to a partly matched group.

`params.enabled` persists activation without a database migration. An omitted value keeps existing rules active for compatibility. Disabled rules are excluded from normal runs; explicitly submitting a disabled rule ID is refused. Rule edits and activation clear affected saved results, while follow-up notes remain intact. Audits retain the actor and approved parameters. Preview evaluates an edited rule in its saved position, even when that rule is inactive. Preview and test use read-only sessions. `GET /matching/columns` exposes both declared columns and additional cleaned-row columns for the editor.

The additive `totals.linked` preserves the count of POS sales connected through both stages. Known promotions, fees and rounding remain explained. Withdrawal-to-bank shortages are separate from settlement-to-withdrawal rounding. Unlinked settlements use `No approved bank link`; this does not claim that the money is absent from the bank. The new mismatch reasons are `Sale and settlement amounts differ` and `Bank payout amount differs`. Andrew's result labels and Taufiq's agent/integration must use these updated meanings and current reason facets.
