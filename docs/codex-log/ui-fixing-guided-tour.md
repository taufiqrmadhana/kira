# Guided workflow tour

- Time: 2026-11-07, 15:08 Asia/Jakarta.
- Task: Add a deterministic guided tutorial launched from Kira chat, with a visual cursor, spotlight and explicit navigation controls.
- Merged: no. No commits or pushes by this task.

Added `GuidedTour.tsx`, `GuidedTour.css`, `tourSteps.ts` and focused tour tests. Updated App and ChatPanel integration and added `data-tour` anchors to existing workflow areas. The tour covers client selection, all three upload sources, conversion and upload rules, the cleaning standard and changed-cell evidence, both matching stages, result review/Excel export and Match analysis. Content describes the real workflow without showing invented results.

The Take a tour control is independent of model access and stays available after a chat-history error. It is disabled while chat work or approval decisions are pending. The chat remains mounted while hidden, preserving its draft and approval state. Exiting restores the original route, query, hash, sidebar state and scroll position; scroll restoration waits briefly for read requests to rebuild the original page. Changing client or unmounting removes the tour and its listeners/timers.

The tour routes only to existing pages and highlights real DOM areas. It never clicks the highlighted action, sends a chat request or executes an upload, conversion, rule decision, matching run or export. A locked later stage highlights its disabled stepper control and explains the prerequisite. Missing targets receive an honest message while Previous/Next remain usable. Unconverted upload rules have a separate explanation from a locked conversion step.

Autoplay advances every ten seconds after a target is ready; Previous and Next reset the timer, Pause stops it, Resume restarts it, and the final step waits for Finish tour. Escape exits globally. The guide cursor persists between targets so its position transition shows movement. Reduced motion starts paused and removes motion. The tour uses a modal dialog, traps keyboard focus, restores focus to the chat's launch control, and announces each step's title, explanation and unavailable-state message. Dialog placement is constrained to the viewport, with a scrollable card when space is limited.
